## Research and chosen direction

The user's [daily.dev article](https://daily.dev/posts/half-life-2-is-now-playable-in-your-browser-thanks-to-a-three-month-project-from-a-teenager-4f1oga4qq) points to slqnt's browser port. The [author's June 24 write-up](https://slqnt.dev/blog/hl2-in-web) describes adapting the existing Portal port, using `steam_legacy` assets, tracing files opened by each map to build data packages, and fixing HL2-specific rendering, gameplay and persistence defects. Facial animation was disabled for stability. These are the author's reported results, not verification of this project's runtime.

The public [weliveinhell/source-engine reference](https://github.com/weliveinhell/source-engine/tree/63f8364fe7b22b239e72dfb5f1024665b3a91567) is pinned at `63f8364fe7b22b239e72dfb5f1024665b3a91567`. Its [build script](https://github.com/weliveinhell/source-engine/blob/63f8364fe7b22b239e72dfb5f1024665b3a91567/emscripten/build.sh) keeps engine/client/server as WebAssembly side modules and links a main launcher with pthreads and OffscreenCanvas. The README's SDK commit `2d480a1b7c7a34a354188d93f3e89190a44a1d21` resolves `latest` to Emscripten **4.0.9**; do not substitute today's `latest` accidentally. This reference only claims Portal testing and still lists limitations. The author's exact HL2 fixes have not been located in a public source repository.

Use a clean private checkout of that architecture. Preserve module factories and normal game-system lifecycle. The current whole-archive monolith merges globals; its recovered source disables server lifecycle calls and contains known buffer-upload/base-vertex defects. Repeating those bypasses cannot establish working HL2 gameplay. [Emscripten's documentation](https://emscripten.org/docs/compiling/Dynamic-Linking.html) explains main/side modules and the synchronization requirements when combining dynamic linking with threads.
