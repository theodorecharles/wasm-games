## Causes and corrections

1. `fill_glinfo` detected non-power-of-two textures only through two extension
   strings. WebGL 2 exposes this as core functionality, so the application
   incorrectly reported it unavailable. Indexed tiles were stored with their
   actual dimensions, while `polymost_drawpoly` rounded the UV denominator up
   to powers of two. Only a fraction of each tile was sampled, explaining the
   cropped/enlarged artwork. The canonical browser-only patch recognizes
   OpenGL ES major version 3 or higher; the desktop and ES 2 cases are unchanged.
   The native Chrome log now reports `NPOT textures: 1 (OpenGL ES 3.0)`.
   This follows the [WebGL 2 NPOT texture-access specification](https://registry.khronos.org/webgl/specs/latest/2.0/).
2. The translated custom shaders declared high-precision floats, but samplers
   still inherited their independent low-precision default. On AMD, an R8
   sample used as a subsequent palette index selected an adjacent entry.
   Declaring `precision highp sampler2D;` fixes the real GPU readback failure.
   The independent sampler default is specified in section 4.5.4 of the
   [GLSL ES 3.00 specification](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf).

These are application/native shader corrections. No SDK/WebGL methods,
browser security settings, proprietary artwork or source pin were changed.
The missing custom-shader alpha-test discard remains a separate source-level
gap; it was not the cause of the proven UV cropping.

## Verification

- `test-polymost-npot.mjs` extracts the actual capability detection and UV
  dimension code and translates the production basic Polymost shader pair.
  Generated column-major indexed art is drawn into GLES 3 framebuffers, both
  standalone and at an offset in a texture atlas. Nine sizes, including
  5×7, 19×31, 63×84 and power-of-two controls, exercise 18 draws and **39,960
  pixels per driver**, with a one-channel readback tolerance.
- Both [AMD](duke-npot-amd-2026-09-06.json) and
  [llvmpipe](duke-npot-software-2026-09-06.json) pass the corrected draws and
  nine browser capability cases; nine desktop cases remain unchanged.
  Restoring the old capability detection fails both capability and pixel
  controls on both drivers. Restoring lowp samplers fails on AMD at a 19×31
  tile: blue channel 142 instead of 105. llvmpipe does **not** reproduce that
  precision loss; its permitted higher precision is recorded, not hidden.
- The production basic and extended shader pairs both compile/link on AMD
  and llvmpipe. Original desktop-GLSL controls fail compilation on each.
- The [source audit](duke-npot-source-2026-09-06.json) matches all 1,702 files
  against the unchanged pin plus canonical patches, tree
  `668c88781e5b6880c778bb1bc0a4e933307bab0f`, with idempotent preparation and
  developer notes preserved. Adapter/family/site-contract tests, generated
  JS syntax and Wasm validation also pass. The full family build was not rerun.
