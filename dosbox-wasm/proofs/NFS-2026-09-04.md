# Need for Speed native race checkpoint — 2026-09-04

## Scope and acceptance boundary

The repaired DOS runtime reaches an actual City race, shifts out of neutral,
accelerates, and renders an advancing road scene with non-silent PCM. This is
**native Wasm evidence in Node, not Chrome gameplay acceptance**. NFS mouse
alignment, browser performance/audio, fullscreen and save restoration remain
open. No game has been promoted to Live.

The subsequent [relative pointer repair](NFS-POINTER-2026-09-04.md) supersedes
the mouse investigation and running-image checkpoint below. Chrome acceptance
and the missing showcase assets remain open.

NFS now uses the same CPU-governor repair already deployed for GTA, described
in [the GTA checkpoint](GTA-2026-09-04.md). No additional native engine change
was needed to reach the race. This does not establish that timing was the only
cause of the user's original menu-to-race failure: keyboard navigation bypasses
the still-unaccepted mouse path.

## Native evidence

The test reads the existing 360-file owner-data policy into an in-memory DOS
drive. Host game files are not modified. It applies the same temporary pointer
configuration as the page adapter and simulates a 4 ms minimum timer delay.

The observed menu sequence is Escape through the intro/title, three Down taps
to select Drive, then Enter through the player-name prompt. The native Controls
Setup screen confirms Up/Down for throttle/brake, Left/Right for steering, and
A/Z for gear changes. The car starts in neutral; A engages a gear before Up
accelerates it. Remaining in neutral is not evidence of failed throttle input.

Two 60-second runs with 150–200 ms menu key holds reached the race and drove:

- `/tmp/nfs-native-gear-held.98LNxi`: frame 9 shows 82 mph in third gear.
- `/tmp/nfs-native-regression.SU9mCu`: frame 9 shows 83 mph in third gear;
  frame 12 shows the car farther down the road, with remaining distance reduced
  from 5.1 to 4.8 miles and the race clock advancing from 13.1 to 27.9 seconds.
- The repeat run delivered 2,589 audio buffers, 2,037 with nonzero samples,
  in both the native mixer and page audio-context test double. Late audio and
  changed video continued during the final ten seconds.

These captures show actual driving, but do not measure browser FPS or prove
audible Chrome playback. Captures remain outside the repository with the
owner-data diagnostics.

## Stronger regression checks

`npm run test:nfs` runs the scripted native race. It is also included in the
optional `DOSBOX_TEST_INSTALLED_GAMES=1` suite. The probe now supports:

- normalized SDL canvas clicks, with separate motion settling and button hold;
- requiring the expected DOS program to remain active, rejecting a DOS prompt;
- requiring the fresh default race's 640x400 video mode instead of the 640x480
  menu; and
- requiring changing video and non-silent native/page PCM in the final ten
  seconds, not merely during the intro.

A menu-only negative control exits with an assertion failure because it remains
at 640x480. Its log is `/tmp/wasm-games-nfs-menu-negative-control.log`.
The passing repeated race log is `/tmp/wasm-games-nfs-race-regression.log`.
The ordinary package, adapter, data, native keyboard/pointer, timing, HTTP,
syntax and repository-layout checks also passed.

Fixed-time menu scripts can miss very short key taps; an initial 40 ms sequence
did so. The regression uses longer holds and fails if it reaches the wrong
screen. Its final checks do not replace inspection of the driving captures.

## Remaining mouse and data issues

A native click at the displayed Drive position did not reliably activate Drive.
With simultaneous motion/button events it opened the Ferrari showcase from
the old cursor position; allowing the motion to settle still did not select
Drive. The generic INT 33h pointer probe passing is therefore not sufficient
evidence that NFS's own cursor is aligned. Diagnose its actual mouse-consumption
path before calling this issue fixed.

The showcase path exits to DOS with:
`openhandle - frontend\show\512tr FILE ERROR`.
Neither the curated policy nor the installed NFS tree contains `frontend/show`
assets. This is a separate data limitation; racing itself loads the supplied
track/car assets successfully. No replacement proprietary assets were fetched,
invented, or added to an image.
