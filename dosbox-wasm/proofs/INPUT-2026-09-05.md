## Browser result: incomplete

The Chrome-control skill was used against the existing Jill suite (8016) and
Jazz service (8020), not replacement images. Jill accepted its existing setup,
displayed its native menu and started a normal world map. Its attract demo was
observed separately and is not counted as gameplay. Left-arrow taps no longer
opened the reported modal, but neither one tap nor twelve subsequent taps
produced visible displacement. Held movement is therefore not Chrome-accepted.

Jazz displayed its native menu and attract demo. Enter exited the demo, but
short Down/Enter presses did not visibly navigate/start from the root menu.
Jazz menu operation, save-name entry and gameplay remain unaccepted. Neither
title is marked fully working on the strength of these observations.

An independent, engine-free [keyboard page](../tests/keyboard-browser.html)
records normal trusted DOM events without synthesizing input. The same Chrome
keypress operation delivered the correct ArrowLeft, ArrowDown and Enter codes,
but their observed down/up intervals were only 1.8, 1.1 and 2.2 ms respectively.
This establishes a tap-only testing limitation, not a complete diagnosis of
every missed game input. It does not establish what a held physical key does.
No artificial minimum key duration or game-control bypass was added.

## Native keyboard coverage

The actual DOS BIOS diagnostic now covers 70 cases: all lowercase letters,
all Shift-uppercase letters, digits, arrows, Escape, Backspace and Enter.
The source-only assembly probe takes its record count from the test runner;
the default remains eight for compatibility with the original diagnostic.

All 70 cases pass both the current staged engine and the exact native binaries
extracted read-only from the running Jill suite. Jazz serves identical native
JS/Wasm hashes. These are real DOS ASCII/scancode results, not a stub mapper.

- [Current staged result](keyboard-bios-2026-09-05.json).
- [Current lab result](keyboard-bios-live-2026-09-05.json): Wasm

  JS `f90ece402ce7e23e323281b55774d10f4dc8d6d2caa9b7fdf7f58935bdb3b104`.

The historical lab artifact predates the CPU-cycle diagnostic export. Its
explicit `--keyboard-only` test omits that unrelated capability assertion.
Normal release tests still require the export and run the complete native
suite; their gate was not relaxed. No native binary was rebuilt in this pass.

The installed-title diagnostic now permits a shorter sampling interval for
observing input transitions. Its generic success result remains a launch/
activity check, not proof that all requested movement occurred. Screenshots
must be inspected before making a movement claim.

## Installed Jill movement and package checks

The exact live Jill/Jazz native binaries were also exercised with Jill's owner
installation mounted read-only into a disposable native test. After answering
its fresh audio/joystick/video setup and entering the normal map, a one-second
Right hold at 11.5 seconds moved Jill to the gem gate. A one-second Left hold
at 14.5 seconds moved her away again. Both inspected frames show the normal
map, not the attract demo or a modal. These are native queue inputs, not Chrome
keypresses, and do not establish browser-held movement or level gameplay.

Evidence: [after Right](jill1-native-right-2026-09-05.png),
[after Left](jill1-native-left-2026-09-05.png), and
[one-second samples](jill1-native-samples-2026-09-05.json). The run used
`test-installed-runtime.js`, `DOSBOX_NATIVE_SAMPLE_MS=1000`, a 17-second
duration, and keys Y/Y/N/V/Enter/Enter at 1/1.8/2.6/3.4/4.2/5.5 seconds before
the two holds. It reported 349 frame updates, 342 changing frames and 425
nonzero audio callbacks; PCM activity is not an audible-listening check.

The no-rebuild package gate initially found an outdated staged shared-shell
copy. Refreshing that generated copy from the current adjacent framework
resolved the mismatch without editing the framework or replacing live images.
Its runtime, shell and console regression suites pass. The complete DOSBox
`DOSBOX_SKIP_BUILD=1 bash dosbox-wasm/scripts/test-web.sh` rerun passes: nine
adapter variants, data manifests, CPU timing, 70 BIOS keys, actual DOS mouse
coordinates/clicks, package contracts and HTTP/private-data boundaries. No
native rebuild or Chrome test of this refreshed staged shell is claimed.
