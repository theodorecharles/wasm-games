## Automatic CPU cycles

The browser patch made `wrap_delay` a no-op while leaving DOSBox's cycle
governor dependent on its measured sleep time. It also counted cooperative
browser yields as emulation work. The resulting estimates were especially bad
with delayed timers. The HTML timer model imposes a 4 ms minimum on deeply
nested timers: [HTML Standard](https://html.spec.whatwg.org/multipage/timers.html).

`WasmIdleAccounting` now measures actual idle intervals and outer-loop yields,
without double-counting overlapping waits or dropping fractional milliseconds.
The governor subtracts that time from CPU work. Yielding still occurs only in
the safe outer loop; nested page-fault/virtual-I/O/idle guards remain unchanged.
Fixed-cycle modes and the existing cycle limits remain intact.

Evidence:

- The deterministic probe compiles the **production** `increaseticks` function
  with a synthetic clock. With the old function, a 3,000-cycle starting budget
  collapsed to the 200-cycle floor; the regression failed. The repaired function
  converges from both low and excessive starting budgets under 1 ms and 4 ms
  timer delays, and preserves a fixed 12,345-cycle configuration.
- A real GTA Wasm launch with a simulated 4 ms timer minimum sampled old cycle
  budgets of 1,322 / 590 / 868 / 1,336 / 1,892 / 2,370 at five-second intervals.
  The repaired build sampled 53,603 / 58,988 / 60,219 / 57,236 / 54,651 / 49,341.
  These are governor settings, **not** browser FPS or MHz measurements.
- Native captures subsequently show the setup menu, city selection, and the
  actual street scene with moving traffic. The scripted test sends sustained
  movement and an attack, but browser control responsiveness remains unproven.

Timing samples: `/tmp/gta-cycle-clamped.hJ8aGv/samples.json` and
`/tmp/gta-cycle-fixed.kKXHG9/samples.json`. The negative-control log is
`/tmp/wasm-games-dos-timing-negative-control.log`.

## Digital audio

The supplied `GTADOS/DIG.INI` contains only `ECHO is on`; the curated manifest
correctly excludes this mutable setup file. A fresh game consequently showed
**Digital Audio: None** and produced zero non-silent audio callbacks.

GTA's own Miles setup successfully auto-detected the emulated Sound Blaster 16
and generated an `SB16.DIG` configuration at I/O address `220h`, with IRQ/DMA
auto-detection (`-1`). `web/gta-sound.ini` supplies those settings only when
the browser's restored `GTADOS/DIG.INI` is absent. Existing settings, including
an empty file or an explicit no-audio selection, are never overwritten.
The new file is marked dirty for persistence. Owner files and host data were
not modified; CD music is not added or claimed.

The 42-second native street-scene run recorded 1,814 scheduled audio buffers,
of which 940 contained nonzero samples in both the native mixer and page audio
handoff. Captures and samples are in `/tmp/gta-native-audio-play.SoggGq`.
This proves PCM delivery through SDL's WebAudio path into an audio-context test
double, not audible Chrome playback.
