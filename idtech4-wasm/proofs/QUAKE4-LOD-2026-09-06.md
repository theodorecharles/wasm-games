# Quake 4 sampling-gate correction — 2026-09-06

Status: **remaining software sampling discrepancy explained; portable packaging
gate corrected and passing**. No production renderer, shader, JS/Wasm, image,
owner data or live service changes. RTCW SP remains untouched; Blood deferred.

## What was wrong with the gate

The retained vendor-exact test still reports 9/128 isotropic differences on
both Mesa 25.2.8 llvmpipe/LLVM 20.1.2 and host Mesa 26.1.6/LLVM 21.1.8. Its
maximum difference is five channel values. AMD passes. The shader already
matches the same-footprint native border oracle on all three drivers.

An independent native probe, `tests/gl-border-lod.c`, loads **no game helper**.
It compares implicit sampling, explicit mathematical LOD, `textureQueryLod`
and a diagnostic model of the software driver's LOD calculation. The model uses
one derivative pair per 2×2 quad and a piecewise-linear logarithm. Together they
reproduce every implicit RGBA8-rounded pixel exactly: 1,936 samples on each
software driver. Fast log with fine derivatives, or queried LOD alone, does not.
AMD does not match this software-specific model.

This agrees with Mesa's actual
[LOD selector](https://raw.githubusercontent.com/chaotic-cx/mesa-mirror/mesa-25.2.8/src/gallium/auxiliary/gallivm/lp_bld_sample.c),
[quad selection](https://raw.githubusercontent.com/chaotic-cx/mesa-mirror/mesa-25.2.8/src/gallium/auxiliary/gallivm/lp_bld_sample_soa.c)
and [fast-log implementation](https://raw.githubusercontent.com/chaotic-cx/mesa-mirror/mesa-25.2.8/src/gallium/auxiliary/gallivm/lp_bld_arit.c).
The fast log uses the exponent and mantissa of squared footprint size, followed
by a factor of one-half. This is a diagnostic explanation, **not game code**.

Exact equivalence to that optimization is not a portable sampling requirement.
[OpenGL 4.6 §8.14.1](https://registry.khronos.org/OpenGL/specs/gl/glspec46.core.pdf)
allows bounded footprint approximations. Default shader derivatives also admit
fine or coarse local differencing under
[GLSL §8.14.1](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.html#derivative-functions).
No driver setting or texture-filtering mode was changed to obtain a pass.

## Independent numerical verification

`tests/q4-border-cpu-reference.mjs` calculates UVs, finite differences, mip LOD,
texel values, border taps and trilinear interpolation independently in double
precision. It reads no GPU derivatives, queried LOD or production helper output.
`tests/gl-border-contract.c` records actual production-helper GL pixels and the
exact packaged converted builtin texture calls in GLES.

All 16 combinations of four texture shapes, two border alphas and implicit/
projected sampling are checked. Each context must match a single complete
fine/coarse derivative policy; the test does not select convenient values per
pixel. The original **one-channel-value tolerance is unchanged**.

- AMD: coarse policy, 15,488 channels across GL/GLES, zero mismatches.
- Host software: fine policy, 15,488 channels, zero mismatches.
- Older build-container software: fine policy, 15,488 channels, zero mismatches.
- GPU mutations that discard mips or substitute edge texels both fail in every
  context, with thousands of mismatching channels.

Exploratory failures are retained, not presented as renderer failures: the first
CPU fixture incorrectly assumed derivative-grid alignment for an odd-height
window. An even 12×12 target now supplies a helper lane around the same 11×11
sample grid. A second check incorrectly assumed only fine derivatives; AMD uses
coarse ones. The final records are `quake4-lod-cpu-*-2026-09-06.json`; earlier
`contract`/`contract-aligned` records preserve those rejected fixture assumptions.

## Packaging behavior

`test-q4-border-validation.mjs` replaces the vendor-exact command in
`stage-site.sh` and validates the **staged** JS route. It requires:

1. The unchanged native same-footprint border oracle, in both GL and GLES.
2. All existing invalid-substitution checks and anisotropic negative control.
3. The independent CPU contract and both broken-sampler controls.

The old test and fixture remain byte-identical. A nonzero raw exit is accepted
only at the exact hash-pinned historical vendor-isotropic assertion, with all
affected rows constrained to implicit/projected trilinear sampling. Every later
native-border assertion is independently enforced. Missing output, errors,
timeouts, other failures and a changed historical runner remain fatal.

The new gate passes on AMD and both software versions at anisotropy one; AMD
and older software also pass at 16. The software raw status remains **1 with nine differences**
in the new report. The historical matrix command still fails under its old
vendor-exact definition; its underlying all-16 same-footprint results remain
valid. This is a corrected component criterion, not a claim those old runs passed.

Canonical source/build/package and retained quad/intro/mip evidence audits
remain unchanged. No full-site restaging or live deployment was performed;
the changed staging command and shell syntax were checked separately.
The new evidence audit independently recomputes all 46,464 CPU channel checks,
3,872 exact software-model pixels and broken-sampler failures, and pins 20 hashes.
