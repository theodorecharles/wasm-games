`alcOpenDevice` always returns NULL. It now links
`src/sys/emscripten/openal_emscripten.cpp`, adapted from this family's existing

across repeated queries and stopped queues can be drained. Optional OpenAL

## Renderer startup work completed in source/build

The existing ES 3.00 interaction shaders compile/link in the local Mesa EGL
test. That proves shader validity, not successful engine initialization.
The following incompatible startup assumptions were corrected:

1. `src/sys/sdl3/sdl3_backend.cpp` calls
   `emscripten_webgl_get_proc_address`. Emscripten 6.0.6's `system/lib/gl/gl.c`
   shows this only searches exact WebGL APIs. Its compatibility resolver,
   `emscripten_GetProcAddress`, additionally resolves suffix aliases and the
   legacy client-array/ARB shader-object wrappers. The new resolver keeps exact
   WebGL APIs first, then uses the public `eglGetProcAddress` compatibility
   resolver. Actual GLEW initialization now resolves the required wrappers.
2. `R_CheckPortableExtensions` in `RenderSystem_init.cpp` requires desktop ARB
   texture-env and assembly-program extensions. The linked compatibility layer
   advertises EXT texture-env variants, while the browser interaction renderer
   executes GLSL ES instead of ARB assembly. Startup now checks those EXT names,
   records ES 3.0 rather than a desktop context, queries the actual texture and
   vertex limits, and clamps fixed-function texture state to the engine's eight
   slots. Unsupported ARB assembly, mapped buffers, framebuffer-sRGB switching
   and texture LOD bias stay disabled.
3. `R_CanUseGLSLPrograms` itself rejects GLSL when ARB vertex/fragment assembly
   programs are absent, preventing the existing browser branch in `R_ARB2_Init`
   from selecting its ES path. The browser gate now checks ES 3, all required
   GLSL functions, at least five texture image units and twelve vertex attributes.
   The inhibit-program and dedicated-server guards remain intact.

`glMultiTexCoord2fARB`, used by a special-effects quad but absent from the SDK,
now appends each texture unit's UV pair to the legacy layer's actual immediate
vertex stream and attribute layout. The MAIN_MODULE executable objects are
compiled as PIC so its imported JS callback can appear in the function table.
