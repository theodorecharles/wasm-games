# Doom 3 multiplayer inline sound mixer — 2026-09-06

## Reproduced failure and repair

Unchanged v6 (`729fd8035b80280ace9c9c29cb71ec3649820f20deee190f42e717f8cc26dfc5`,
port 32925) loads sound buffers and has a running AudioContext, but reports
**zero scheduled playback starts throughout multiplayer**. This occurs in
both actual Chrome clients, across Delta Lab, Tomiko Reactor and Frag Chamber.
The [last gameplay baseline](d3-mp-audio-v6-baseline-2026-09-06.json)
has 172 buffers and zero starts. After that same client uses native
`disconnect`, its [main-menu observation](d3-delta-controlled-fresh-disconnect-2026-09-06.json)
has 343 starts. The other client likewise reaches 147 starts only after
[disconnect](d3-delta-controlled-transition-disconnect-2026-09-06.json).
This is browser playback scheduling evidence, not a listening test.

The pinned d3wasm source defaults `com_asyncSound` to **0**, meaning inline
mixing. `Common::Frame` skips `Session::Frame` during active network play;
the only inline `soundSystem->AsyncUpdate()` call was inside that skipped
session path. The async timer handles modes 1 and 3, not 0. Consequently the
native game never schedules its sounds during the normal MP frame loop.

`patches/d3wasm-browser.patch` now calls the same mixer in the **active-network
branch only**, when `com_asyncSound == 0`, after `idAsyncNetwork::RunFrame`.
Checking the current network state after that call also covers joining and
disconnecting within a frame. The single-player/session path and other mixer
modes are unchanged. No browser audio bridge, renderer, shader, native server,
bot logic, cvar default or retail asset was changed by this repair.

## Rendering lead and limits

Follow-up: the [native clock/lighting diagnostic](D3-LIGHT-CLOCK-2026-09-06.md)
now reproduces the old Delta roundtrip blackout and verifies the v7 repair,
with independent mixer-removal and same-camera amplitude controls. It does
not close full-map or release acceptance; the original lead below is historical.

Skipping the mixer also prevents normal in-match advancement of
`CurrentSoundTime`. In `snd_emitter.cpp`, `CurrentAmplitude` reuses its cached
result while `ampTime == GetCurrent44kHzTime()`; both the cache time and
amplitude start at zero. `Material.cpp` uses that result for the native `sound`
expression, including sound-driven lights/flares. This dependency can leave
lighting stale or zero and may explain some dark surfaces without a shader
change. Browser telemetry here does not directly measure the native sound
clock; the exact extent in Delta Lab still requires controlled visual proof.
Do not treat it as full-map rendering acceptance.

The earlier [v6 controlled roundtrip](D3-DELTA-DIAGNOSTIC-2026-09-05.md)
again reaches fresh Delta, votes Delta→Tomiko→Delta and admits a second human.
The attempted same-player view is interrupted by pause/capture behavior,
missed short Ctrl pulses and automatic round/map cycling. Its saved
[follower attempt](d3-delta-controlled-follower-attempt-2026-09-06.jpg)
is an intermission spectator view, **not** a matched-camera rendering oracle.
Original client [active play is restored](d3-delta-controlled-restored-play-2026-09-06.jpg),
both clients disconnect natively, and [natural idle](d3-delta-controlled-final-idle-2026-09-06.json)
leaves no peers, bots, native child or temporary session.

Remaining gates include audible quality/spatialization, sustained controls and
pointer capture, controlled Delta rendering, actual browser malformed-packet
recovery, and full SP/RoE campaign/save regression before promotion. The
existing `guisounds.wav`, script-constant and native asset warnings are not
hidden or declared fixed. RTCW SP and the user-deferred Blood crash are untouched.
