# Doom 3/RoE saved trace-model ownership — 2026-09-06

## Repair and evidence

The uncached trace-model warning is fixed in the isolated **v8** candidate.
Native/Wasm regression controls and Chrome loading each original v7 save twice
pass. New named saves survive a full page reload and restore gameplay; native
pause/resume and normal quit also pass without the warning. This completes the
targeted repair, not full campaign or production acceptance.

The preceding [v7 campaign checkpoint](D3-CAMPAIGN-SAVES-2026-09-06.md) retains
the actual failure. Each final log contains **two** instances of
`idClipModel::FreeTraceModel: tried to free uncached trace model`: one when
the comparison load shuts down the restored map, another on native Quit
Current Game. This was not just a cosmetic message from an unrelated process.

`InitFromSaveGame` calls `LoadMap`, which initializes the clip system and its
default trace model. Later `idRestoreGame::RestoreObjects` replaces the trace
cache and initializes every saved entry's reference count to zero. Entity
restore rebuilds entity references, but not the clip-owned default reference.
That model keeps an old index with no corresponding restored ownership; a
different saved cache order could also make it refer to the wrong shape.

The repaired SaveGame call goes through `idClip::RestoreTraceModels`. It first
releases the old default/scratch references, restores the saved cache, then
reacquires the default by its existing shape. Saved indices and mass properties
remain intact for entity restoration. The scratch model is regenerated by the
next bounds trace. `Shutdown` shares the same cleanup helper. Both base and
RoE receive the repair through their canonical patches; the original cache
read/write, allocation and warning-guard methods are unchanged.
