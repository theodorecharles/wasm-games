# Quake 4 Chrome checkpoint — 2026-09-05

Quake 4 SP now renders its animated main menu in real Chrome and accepts menu
navigation through Single Player → Mission → New Game. **Campaign gameplay
and audio are not accepted. No live service was replaced.**

## Renderer fixes proved through native startup and Chrome

The previous candidate exposed three consecutive failures with the owner's
retail PK4s, mounted read-only in an isolated container:

1. Direct OffscreenCanvas context creation bypassed the Emscripten callbacks
   that initialize legacy colour, matrices, texture state and client arrays.
   Running the same callbacks used by the SDK's context creation removes the
   `glColor4f` null `clientColor` crash. The native regression now calls the
   production context function instead of manually initializing emulation.
2. The SDK's legacy `glDrawBuffer` aborts. The compatibility entry point now
   delegates to WebGL2 `drawBuffers([mode])`, retaining browser validation.
3. The SDK's legacy indexed-draw path assumes unsigned-short indices, while
   Quake 4 uses unsigned-int indices. The bridge retains the SDK's attribute,
   shader and matrix preparation and submits the original index bytes/type.
   CPU source bounds and temporary-buffer capacity are checked. Native tests
   cover indices 65536 and 70000, CPU uploads, GPU index offsets, narrower
   supported types and invalid inputs. Indices are not narrowed or rebased.

The native GL fixture substitutes the GPU and renderer shader preparation;
those tests are not GPU/gameplay proof. Chrome supplies the separate actual
menu-rendering evidence. The scene animated and physical menu selections
worked using approximately one-second left-button drags. An initial brief
click alone did not show a transition; sustained keyboard movement was not
tested in this pass.

## Remaining campaign failure

Selecting Start Game at the default Corporal difficulty begins
`game/airdefense1`, then reports:

```text
ERROR: file <ChoiceVals>, line 1: newline inside string
```

The engine subsequently aborts because exception catching is not enabled in
the main module. Neither the malformed value's origin nor the appropriate
exception recovery path has been repaired. Do not bypass the parser, swallow
the exception or call menu startup campaign acceptance.

The menu run also reports an incompatible desktop GLSL 1.30 SMAA shader and
disables SMAA. Special effects, skinning and map rendering still need testing.

## Focus/audio bridge built, not yet Chrome-verified

Chrome showed a running AudioContext and 280 loaded buffers, but zero sources
or playback starts. The native focus query always returned false because the
direct worker renderer has no SDL desktop window; the session's unfocused
audio policy consequently selects no sound world.

The Quake 4 adapter now sends actual page focus/visibility at startup and on
focus changes. The worker retains changes received before native initialization.
The native platform reports that focus, releases held input on blur and
refreshes the existing session audio policy after initialization. Desktop
behavior and the other engines' worker messages remain unchanged. This does
not turn off `s_muteUnfocused` or force an always-focused state.

Native extracted-production tests cover initial focus, blur, duplicate events,
input-release notification and session audio refresh. Adapter/worker tests
cover hidden pages, actual focus restoration and pre-main ordering. Audible
playback, blur/resume timing and sound quality still need Chrome verification.

Chrome control timed out during a subsequent diagnostic run, including tab
recovery after the documented window reconnect. Browser/extension/native-host
checks passed. Further UI tests are paused pending recovery of Chrome control;
its troubleshooting instructions recommend reinstalling the Browser plugin
from the plugin UI if that reconnect still fails. Temporary diagnostic logging
was removed from the prepared source before the final build.
