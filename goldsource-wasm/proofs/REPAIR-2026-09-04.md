## Shared log-selection repair

The old framework `log()` used `console.textContent += ...`, replacing every
existing text node for each new engine message. It also assigned the bottom
scroll position unconditionally. This invalidated the user's selected error
text and pulled readers away from older messages. The stylesheet already
allowed text selection; a game-specific CSS override would not fix the cause.

The canonical fix is in the sibling framework checkout, not the GoldSource
adapter:

- `../wasm-game-framework/dist/wasm-game-bootstrap.js` appends/batches text
  nodes, follows the bottom only when the reader was near it, and keeps the
  existing 80,000-character history threshold with a 60,000-character tail.
- A selection intersecting the log freezes its DOM and scroll position while
  retaining at most 60,000 characters of pending output. `selectionchange`
  flushes that tail when selection clears, even without another engine message.
  A selection elsewhere does not pause the log.
- `../wasm-game-framework/test/bootstrap-console.test.js` executes the actual
  production logger with a small DOM test double. The framework document test
  includes this regression in `npm test`.

These paths are relative to the `wasm-games` workspace root. The framework
changes remain local and uncommitted. Framework version **0.9.6**, pinned HEAD
`ebb1ebe35ad8224a9080279a6529414db42d3284`, is unchanged. This is a local
development build from that checkout plus the logger change, not a newly
published immutable framework release. The documented local framework build
workflow includes uncommitted framework changes; no downstream pins were
mechanically updated and no game-local shell fork was introduced.
